# SuperAutoplus 界面优化方案

本方案参考 DeepSeek 官网的简洁信息层级、留白和克制的视觉表达，适配 SuperAutoplus 现有管理工作台。优化范围是页面布局、公共组件、样式和可访问性；保留现有路由、数据接口、认证、任务操作、账号管理及设置功能。

## 参考依据与边界

2026-09-29 读取的 [DeepSeek 中文官网](https://www.deepseek.com/) 与 [英文官网](https://www.deepseek.com/en/) HTML 展示以下结构：顶部产品导航和语言切换、发布公告、居中主标题、对话/API/桌面端三个产品入口，以及按产品、研究、法务与安全、招聘分组的页脚。

当前 HTML 观察只用于确认内容结构。本次未直接读取官网的完整 CSS，也未完成官网各视口的浏览器测量。下文中的颜色、字号、间距、圆角、阴影和断点均为本项目的设计适配值。[历史视觉提取记录](https://www.getmd.design/library/deepseek.com)与 [DeepSeek 风格设计系统整理](https://www.shadcn.io/design/deepseek)仅用于辅助理解灰白画布、蓝色识别和轻量入口卡片的视觉方向。

官网是产品入口页，项目是持续操作的后台工作台。因此保留工作台侧栏和信息密度，把官网的清晰层级转化为“页面说明 → 常用入口 → 关键数据 → 详细状态”的布局。

## 设计令牌

样式通过 CSS 语义变量集中管理。页面和组件引用变量，避免重复硬编码主题颜色。

| 类别 | 浅色适配值 | 使用规则 |
| --- | --- | --- |
| 画布 | `#d6dbdc → #f1f5f9 → #ffffff` | 顶部冷灰渐变逐渐过渡到白色 |
| 卡片 | `#ffffff` | 表面清楚，少量透明度只用于不影响阅读的区域 |
| 次级表面 | `#eef2f9` | 表头、分组、输入辅助区与状态容器 |
| 主文字 | `#182338` | 页面标题、数值、关键标签 |
| 正文 | `#475569` | 说明、导航和常规内容 |
| 辅助文字 | `#596980` | 说明文字保持可读；不使用浅灰承载必要信息 |
| 品牌蓝 | `#4d6bfe` | 图标、强调边界、选中背景和焦点识别 |
| 可读蓝色文字 | `#3e58d5` | 白底的小字号链接与强调文字使用更深蓝色 |
| 主要操作 | `#405de6`，hover `#344bc0` | 使用白色文字，实算对比度分别为 5.35:1 / 7.21:1 |
| 边框 | `#dbe2ee`；控件 `#8290a6` | 单像素边界，输入控件使用更清晰的边线 |
| 圆角 | 控件 `8px`；卡片 `16px`；大面板 `18px` | 胶囊形仅用于状态徽章等紧凑标识 |
| 轻阴影 | `0 0 0 1px #f1f5f9, 0 2px 4px rgba(15,23,42,.05), 0 12px 24px rgba(15,23,42,.05)` | 普通卡片轻微提起；弹窗单独增加层级 |
| 间距 | `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px` | 以 4px 和 8px 节奏组织，卡片内边距通常 16–24px |
| 动效 | `140–150ms`、`200ms` | 交互反馈、导航展开分别选用 |

字体采用本地无衬线系统栈：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`，仅使用本机已有字体。不发起外部字体请求。正文 14–16px、行高 1.5–1.8；辅助标签 12–13px；卡片标题 16–18px；首页主标题随视口在约 30–44px 之间变化。数字使用等宽数字特性，长说明限制行宽。

暗色主题保持相同的语义、间距和组件轮廓，将画布映射到深蓝灰、卡片映射到略亮的深色表面、正文映射到浅灰、辅助文字映射到中浅灰。边框使用低透明度浅色，焦点和链接使用更亮蓝色。成功、警告、错误继续沿用状态语义，同时保留文字或图标；主题切换不改变业务状态含义。

## 页面与组件模式

### 导航与首屏

- 桌面保留可折叠侧栏，品牌、主要功能、设置和主题/语言操作形成稳定分区。当前页面通过背景与文字共同标识，提供 `aria-current`。
- 移动端使用顶栏和侧栏抽屉；打开后有遮罩、明确关闭方式、Escape 关闭及焦点回到触发按钮。跳转页面后关闭抽屉，避免遮挡内容。
- 仪表盘首屏保留项目品牌与短说明，下方使用账号、任务、设置三个直达入口；统计和桌面状态继续显示真实接口数据。
- 每个页面保持一个主要标题，标题说明与操作工具栏分开。次级动作保持克制，主要业务动作可以继续使用蓝色按钮。

### 表单与按钮

- 控件采用 8px 圆角、单像素边框和统一背景；默认、hover、focus、disabled、invalid 状态清楚可辨。
- 输入项保留可见标签或等效可访问名称，说明文本通过 `aria-describedby` 关联。密码、验证码和密钥字段保留现有输入类型及提交规则。
- 默认控件和图标按钮的触控区域至少 44px；紧凑桌面表格动作在触屏视口扩大点击区域。
- 主要按钮、描边按钮、ghost 和危险按钮继续使用现有组件变体。加载时保留文字反馈，禁用重复提交；危险操作保留已有确认流程。
- `focus-visible` 使用至少 2px 高对比焦点轮廓与偏移，不依赖阴影或颜色变化单独表达焦点。

### 表格、卡片与状态

- 表头使用浅色次级表面，行分隔线和 hover 背景帮助追踪。主要数据左对齐，数值和操作维持一致对齐方式。
- 小屏保留横向滚动容器，页面本身不横向溢出；不隐藏操作、关键状态或业务列。长文本采用换行、截断加完整内容入口等既有行为。
- 卡片使用 16px 圆角、16–24px 内边距和轻阴影。只给可点击卡片增加 hover 反馈，普通信息卡片避免表现得像按钮。
- 状态徽章保留成功、警告、错误、中性分类，以文字配合颜色。空状态、加载状态和请求错误各自保留明确反馈。
- 数据图形保留数值和文本说明；环形图本身标为装饰，旁边提供等效数值、标签及比例，进度信息不只依靠条形宽度表达。

### 弹窗

- 统一 18px 面板圆角、主题表面和柔和遮罩。面板最大高度基于 `100dvh`，正文内部滚动，底部主要操作可达。
- 本次移动导航使用 Radix 提供标题关联、焦点约束、Escape 和关闭后焦点恢复。现有业务弹窗沿用原有逻辑，仅统一外观与滚动高度；未逐一重构既有自制弹窗的键盘行为。
- 窄屏保留至少 16px 外边距；长表单与日志不会把关闭按钮或提交按钮挤出可操作范围。

## 响应式与可访问性

| 视口 | 布局规则 |
| --- | --- |
| `<768px` | 侧栏抽屉；主内容单列；页面边距 16px；入口卡片堆叠或按可读宽度排列；工具栏换行 |
| `768–1023px` | 保留桌面导航；优先两列统计，复杂内容仍为单列，避免压缩输入和表格 |
| `1024–1279px` | 首页入口三列、统计四列，详细图表保持单列；状态分组可三列 |
| `≥1280px` | 图表双列、桌面状态三列；内容设最大宽度 1280px，超宽屏保持阅读行长 |

本次修改的导航、表单、表格、按钮以键盘可达为目标，跳过导航链接可到达主内容；纯图标按钮具有可访问名称，装饰图标从可访问树隐藏。正文对比度以 WCAG AA 为目标，错误和状态不只靠颜色区分。保留系统主题与中英文切换；英文布局的实测范围、200% 缩放等待验项目见下方验证记录。

动效主要使用颜色、透明度与短距离位移，不引入持续装饰动画。`prefers-reduced-motion: reduce` 时取消非必要动画和过渡，保留即时状态变化。

## 业务兼容要求

保留现有路由、API 地址与请求参数、认证状态、主题与语言偏好、侧栏折叠持久化及页面数据加载。账号查询和操作、注册与任务流程、代理和设置、公开工具页、日志和已有确认行为继续使用现有实现。视觉调整避免修改数据计算、权限判断、轮询和提交逻辑。
